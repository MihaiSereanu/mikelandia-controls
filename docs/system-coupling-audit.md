# Remaining system coupling

Source audit updated after the PC presentation isolation audit, 26 October 2026. These assignments guide later changes; they do not establish live compatibility.

## Boundary established

`src/systems/registry.mjs` selects the exact system integration. Application composition shares a resolver between the session and command gateways. Selection waits for a real system ID and remains fixed for that application lifetime.

The D&D integration owns actor eligibility, record projection entry points, collective references, command handler selection, actor-type restrictions, and capability policy. Legacy projection helpers remain in their existing files. Native operations and execution orchestration now live in `systems/dnd5e/legacy-gateway.mjs`, selected through the shared execution adapter contract.

The shared command gateway still resolves fresh actor sources and enforces session, ownership, and duplicate-request guards. Fallback gameplay commands and item-menu requests are rejected before D&D helpers or dice listeners run. Unknown systems now have owner/GM identity browsing and deliberate native-sheet access. Their item and rules data remain within native sheets.

`profile-view.mjs` and `features/characters/profile-panels.mjs` supply shared projection/rendering and capability-gated action buttons and explicit resource editors. Warhammer maps player-character fields, native skill groups, and equipped weapon groups for both editions, with native tests/attacks and magic. Spell casting and Wind channelling retain edition-specific native entry points. D&D command IDs remain unavailable in Warhammer and Shadowdark. Shadowdark Player actions use native model methods with config-scoped pre-roll hooks; NPC/Light types retain native access. Weapon calculations and consumption remain native; the shared renderer only displays supplied values and labels.

## PC audit results

The remaining D&D extraction files are legacy code reached through D&D projection/presenter/command paths. The source audit confirmed that profile/native records take their own character shell, have no D&D class/species banner inputs, and use neutral theme defaults. Shared Foundry theme synchronization requires no system-specific change. Item macro creation still requires exact D&D5e, unsupported quickbars stay gated, and native action results remain in each system's Chat. Scene, targeting, token placement, journals, and combat use Foundry documents; their native-system interactions remain live validation work.

Fixed visible policy leaks: legacy character Help gestures, class color/header artwork controls, character Quickbar selection, action-summary settings, and retained D&D collection/favourites preferences. Integration features now control both Settings exposure and direct preference writes. Non-D&D color selection uses the mobile shared picker; the native D&D class picker stays hidden while stored registration defaults remain intact. Unsupported settings are excluded from Restore Defaults, and obsolete header-art migrations do not run outside the legacy integration.

The action-session gateway now checks its integration capability before any D&D message parsing. The application-lifetime resolver is supplied to settings registration, preferences, commands/session composition, and action summaries. No additional RPG semantics, NPC profiles, installed-copy changes, or world edits were added during this audit.
